### 3.5 结果口径说明

- **执行通过**：用例按设计执行完成且满足用例文档写明的断言口径，**不等于被测系统无缺陷**。
- **缺陷复现类用例**：如 TC-API-USER-007（非法手机号），用例预期为"后端拦截；或直接记录成功（缺陷见 BUG 清单）"，断言按文档兼容两种结果并在 Console 记录 BUG-006 复现日志——执行状态记"通过"与缺陷发现并行记录，两者不矛盾。
- **阻塞**：因环境限制（验证码开关关闭、本地单浏览器）无法执行，属环境问题，非产品缺陷。
- **补测记录**：TC-CONC-002 为第 2 轮补测（首轮因数据一致性专项未覆盖而未执行）。补测方法：建用户 → 绑定角色/岗位 → 删用户 → SQL 核验三张表（`sys_user` / `sys_user_role` / `sys_user_post`）。结果：主表逻辑删除（`del_flag` 0→2），两张关联表记录均被清理，用例通过。

## 四、缺陷分析

本轮共发现 **9 个缺陷**：致命 2、严重 3、一般 2、轻微 2。全部经二次独立复现，并通过数据库落库核验确认为真实缺陷（非脚本误报）。

| 编号 | 标题 | 严重程度 | 状态 |
|---|---|---|---|
| #3 | 并发新增重名用户产生重复数据 | 致命 | 新建 |
| #4 | 并发新增重名角色产生重复数据 | 致命 | 新建 |
| #5 | 后端缺失用户名长度校验 | 严重 | 新建 |
| #6 | 后端缺失密码长度校验 | 严重 | 新建 |
| #7 | 后端缺失密码非法字符校验 | 严重 | 新建 |
| #8 | 后端缺失手机号格式校验 | 一般 | 新建 |
| #9 | 新增角色不传 menuIds 返回 500 异常 | 轻微 | 新建 |
| #10 | 登录密码 HTTP 明文传输 | 一般 | 新建（环境整改项） |
| #11 | 字典类型为空提示文案不准确 | 轻微 | 新建 |

> 表中 #3~#11 为禅道缺陷 ID，对应《缺陷详细报告》的 BUG-001~009（#3=BUG-001，依次对应）。

### 缺陷共性分析

1. **后端参数校验缺失（#5~#8）**：长度、格式、非法字符校验只在前端实现，绕过前端直调接口即可写入非法数据，属体系性安全弱点。建议后端统一补齐参数校验。
2. **并发唯一性竞态（#3、#4）**：唯一性校验与插入之间无锁、无唯一索引，并发下产生重复脏数据。建议数据库层对 user_name / role_name 加唯一索引兜底。

## 五、风险评估

| 风险 | 等级 | 说明 |
|---|---|---|
| 并发重复数据污染 | 高 | 生产多用户并发场景必现概率性脏数据，影响账号体系完整性 |
| 绕过前端写入非法数据 | 高 | 恶意调用方可写入弱密码、非法用户名，削弱账户安全 |
| 密码明文传输 | 中 | 本环境 HTTP 明文可登录；生产须启用 HTTPS |
| 验证码未覆盖验证 | 低 | 本轮未启用验证码，验证码逻辑未得到验证，下轮开启后补测 |

## 六、测试结论

1. 核心业务流程（登录退出、用户/角色/菜单/部门/岗位/字典/参数/公告/日志的增删改查、权限控制）功能正确，接口测试 33 条全部通过。
2. 发现 2 个致命、3 个严重缺陷，集中在**并发唯一性**与**后端校验缺失**两类，均为安全与数据完整性问题。
3. **准出建议：暂不建议上线。** 待致命与严重缺陷修复并完成回归测试后，再进入下一轮验收；一般/轻微缺陷可在上线前整改或排期修复。
